### ИИ-аналитик

- Прогноз отказов: тренд параметра к аварийному порогу ПЛК, время до отказа с интервалом и вероятность выхода
  за порог в ближайший час (градиентный бустинг на синтетических траекториях износа, AUC 0,97); перевод в автомобили.
- Детектор аномалий режима (MCD, расстояние Махаланобиса): развивающаяся неисправность видна раньше тревоги ПЛК.
- Модель причин брака по узлам; брак в симуляторе ПЛК зависит от режима (`sim.quality` в реестре контроллеров).
- Вероятностный прогноз месяца методом Монте-Карло и сценарий с предиктивным обслуживанием.
- ИИ-ассистент на OpenAI с инструментами только для чтения, сменный отчёт, офлайн-режим без ключа.
- Прогнозы на 3D-модели и в полосе «Прогноз ИИ» на пульте HMI; демо-сценарии износа на симуляторе.
- Проверки: 14 тестов бэкенда.

### Сценарная студия: вероятностный прогноз месяца

- Единое ядро прогноза `services/forecast.py`, калиброванное по данным: без случайности воспроизводит центр решений
  (4 641 авто, эффекты мероприятий +181 / +63 / 0), отказы — по журналу простоев с частотой и длительностью по оборудованию.
- Монте-Карло: жидкостная модель потока с конечными буферами, векторизованная по прогонам (NumPy), общие случайные числа
  (свой поток на каждую единицу оборудования) для сравнения сценариев. Медиана 4 441, P10–P90 4 374…4 503, вероятность плана и цели, цена нестабильности 204 авто,
  частота узких мест.
- Чувствительность и подбор самого дешёвого плана выхода на цель с заданной уверенностью; применение плана к сценарию.
- Месяц в «Сценариях производства» считается тем же ядром — расхождение 4 641 / 5 327 устранено; цель берётся из настроек.
- API `/api/forecast/*`; блоки «Вероятностный прогноз месяца», «Как выйти на цель», «Что сильнее влияет» в центре решений.
- Зависимость: NumPy. Проверки: 13 новых тестов Python (калибровка, совпадение с центром решений, воспроизводимость,
  буферы, подбор плана, API, скорость).

### 1. Архитектура проекта

- Бэкенд разделён на слои: `api/` — роутеры FastAPI по областям, `schemas/` — модели запросов, `services/` —
  бизнес-логика, `repositories/` — хранилище, `config.py` — пути и окружение; `main.py` стал фабрикой приложения.
  Эндпоинты SCADA — в `api/scada.py`, среда выполнения — в `scada/runtime.py`.
- Фронтенд разложен на `app/` (точка входа и композиция), `features/` (экраны: workspace, analytics, decisions,
  data-source, zones, vehicles, simulation, scada), `shared/` (API-клиент, типы, хуки, форматы, общие элементы)
  и `scene/` с подпапками core, hall, site, vehicles. Хук потока событий и форматтер дат вынесены из `App`.
- Адреса API, команды запуска и тестов не изменились; README получил скриншоты, сценарии использования,
  диаграммы архитектуры и потоков, таблицу API и раздел ограничений.
- Корень репозитория очищен: материалы кейса — в `docs/case/`, журнал изменений — в `docs/CHANGELOG.md`,
  скрипт пересборки геометрии — в `backend/tools/`.

### 2. Производительность 3D

- Детальные GLB получают только 140 ближайших машин в кадре; у Onix и Cobalt три уровня детализации, у машин
  на стоянках облегчённые колёса. Треугольников за кадр — около 2 млн вместо 30 млн.
- Отключён режим прозрачности затенения N8AO, который дважды перерисовывал сцену; тени обновляются 20 раз в секунду;
  на Retina вместо MSAA работает SMAA; качество подстраивается под FPS (плотность пикселей, свечение, затенение).
- Положения машин на стоянке не пересчитываются вместе с родителями каждый кадр; неподвижные части сцены
  не перерисовываются при обновлениях симуляции.
- Сцена не пересоздаётся при смене раздела и не рисуется, пока скрыта; `?perf` показывает раскладку сцены.
- На M4 при одинаковой плотности пикселей: общий вид ≈30 → ≈150 FPS, цех ≈27 → ≈110 FPS.

### 4. SCADA и HMI

- Управление контроллерами линий по PackML через OPC UA: реестр 12 контроллеров, драйвер OPC UA, ядро с тегами,
  тревогами по ISA-18.2, командами с проверкой блокировок и вторым шагом подтверждения, журналом аудита SHA-256
  и историком; роли пользователей.
- Симулятор ПЛК с собственным OPC UA-сервером; участки связаны буферами.
- Пульт оператора `/hmi.html`: лента тревог, схема линии, плитки контроллеров, панель контроллера, тренды, журналы.
- Тревоги ПЛК окрашивают участок на 3D-модели и подписывают его; в карточке участка — состояние ПЛК и переход в пульт.
- Документация: `docs/SCADA.md`; тесты SCADA (PackML, драйверы, OPC UA, API, роли) и E2E пульта.
- Уровень поля и центральный пульт, как на заводе: у каждого контроллера описан шкаф управления (+ШУ, ПЛК,
  модули ввода-вывода, привод) и перечень сигналов на клеммах — 125 DI/DO/AI/AO с адресами `%I`/`%Q`/`%IW`/`%QW`
  и устройствами. Симулятор ПЛК формирует образ клемм из своей логики и публикует его по OPC UA под `IO.<id>`;
  аналоговые — сырыми отсчётами 0…27648, сервер переводит их в единицы параметра. Защита по нижнему пределу
  (расход охлаждения) ждёт выхода на режим, как таймер пуска насоса.
- Экран «Диспетчерская» в пульте: путь сигнала датчики → шкафы по участкам → сервер SCADA → клиенты, сводка сервера
  (контроллеры на связи, теги, обновлений/с, цикл тревог, клиенты, историк, журнал, резервирование), вкладка
  «Сигналы I/O» с фильтрами, блок «Шкаф и сигналы» в панели контроллера. `GET /api/scada/server`, `GET /api/scada/io`.
- Команды линии с центрального пульта (`POST /api/scada/lines/{id}/commands`): остановка и удержание сразу,
  пуск — с подтверждением; сервер проходит по контроллерам по очереди (пуск с конца линии, остановка с начала),
  подаёт нужную цепочку PackML с ожиданием подтверждения ПЛК, заблокированные пропускает с причиной.

### 4. Производственная симуляция и what-if

- Добавлен серверный дискретно-событийный движок: четыре агрегированных ресурса, конечные буферы,
  сохранение ID кузовов и прогресса обработки при отказе, приёмка и карантин на ОТК.
- Оборудование с демонстрационными ID связано с остановкой, блокировкой и отсутствием подачи в 3D.
- Отдельные сессии, WebSocket, HTTP-резерв, восстановление связи и отбрасывание устаревших состояний.
- Сценарии ремонта сравниваются при одинаковых условиях и seed; месяц рассчитывается отдельным прогоном.
- Причины потерь сопоставляются с контрольным прогоном без отказа; ограничивающий ресурс проверяется
  поочерёдным сокращением такта каждого ресурса на 10%.
- Добавлены оценка экономического эффекта и редактируемые предположения.
- Новый интерфейс сценариев размещён в отдельной колонке и общей сетке; после расчёта открывается результат.
- Шрифты интерфейса и 3D-текста перенесены в локальные ресурсы с лицензией OFL.
- Исправлена ошибка дробного шага экскурсии; переключатели кровли и подписей получили aria-pressed.
- Производственные координаты в E2E считываются после обновления реальных мешей; диагностический
  обход сцены включается только через ?e2e=1.

Ограничения: модель сценарная, без MES и заводской калибровки; межцеховой транспорт мгновенный,
подача комплектов не ограничена, календарь и экономические параметры заданы явно.

Проверки: 18 тестов Python, 12 E2E-тестов Playwright с настоящими API и production-сборкой,
проверка TypeScript, сборка и git diff --check. Дополнительно проверен пользовательский
предпросмотр на 5174: отказ конвейера, результат 113 → 122 и месячное сравнение.
