## Требования

| Что | Версия | Зачем |
|---|---|---|
| Python | 3.11+ (проверено на 3.13) | бэкенд FastAPI, модели ИИ, OPC UA-сервер симулятора ПЛК |
| Node.js | 22.18+ (проверено на 24.13) | сборка фронтенда, проверки GLB |
| Браузер | с WebGL 2 | 3D-сцена: Chrome, Edge, Safari, Firefox актуальных версий |

Больше ничего ставить не нужно: тестовые данные кейса, геометрия площадки из OpenStreetMap и GLB-модели
автомобилей лежат в репозитории. Интернет нужен только для `pip install` и `npm install` — и для ИИ-ассистента,
если подключать ключ OpenAI. Для запуска в Docker (сразу ниже) ни Python, ни Node.js не нужны — только Docker
с плагином Compose.

## Docker — одной командой

Самый короткий путь — для показа и пилота:

```bash
cp .env.example .env          # необязательно: порты, SCADA_MODE, ключ OpenAI
docker compose up -d --build
```

Двойник — http://localhost:8080 (`WEB_PORT`), там же `/hmi.html` и `/admin.html`: nginx отдаёт статику
и проксирует `/api` вместе с WebSocket и SSE на контейнер API, поэтому наружу смотрит один порт. Схема OpenAPI
(8000) и OPC UA симулятора (4840) публикуются только на `127.0.0.1` — для отладки и внешних OPC UA-клиентов
вроде UaExpert. Логи — `docker compose logs -f api`.

Изменяемое состояние (`twin.db`, `scada.db`, учётные записи) лежит на томе `allur-state`, а не в образе,
и переживает пересборку; `docker compose down -v` стирает его вместе с томом, и при следующем запуске
хранилище снова заполняется из файла кейса. Полный список переменных compose — в `.env.example`.
Разработка в контейнерах с горячей перезагрузкой: `docker compose -f docker-compose.dev.yml up --build`.

Остальное про развёртывание — [docs/DEPLOY.md](DEPLOY.md): состав стека, переменные деплоя, резервная копия
тома, обновление и откат, проверка после деплоя, HTTPS и выход на контроллеры завода.

Ниже — запуск из исходников: так удобнее разрабатывать, есть горячая перезагрузка и доступны тесты.

## Шаг 1. Бэкенд — порт 8000

Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate                # Windows PowerShell: .\.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
uvicorn app.main:app --app-dir backend --port 8000 --reload
```

Бэкенд готов, когда в логе появилось `Application startup complete`; проверка — http://localhost:8000/api/health.
Окружение ожидается именно в `.venv` в корне проекта: оттуда его берут E2E-тесты.

## Шаг 2. Фронтенд — порт 5173

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Vite проксирует `/api` вместе с WebSocket на `http://127.0.0.1:8000`, поэтому адреса и CORS настраивать не нужно.

## Шаг 3. Открыть

| Адрес | Что это | Вход |
|---|---|---|
| http://localhost:5173 | двойник: 3D-завод, аналитика, центр решений, сценарная студия, ИИ-аналитик | не нужен |
| http://localhost:5173/hmi.html | пульт оператора у линии: мнемосхема, тревоги, команды | `operator`, `engineer`, `viewer` |
| http://localhost:5173/admin.html | админка: цели, допущения, импорт данных, паспорт завода, пользователи, аудит | `admin` |
| http://localhost:8000/docs | схема OpenAPI и ручная проверка запросов | не нужен |

В демо-учётках пароль равен логину; файл — `backend/app/data/scada_users.json` (PBKDF2-SHA256, 200 000 итераций).
На заводе он заменяется через `SCADA_USERS` или подключается AD/LDAP.

Что показывать: [демо-сценарий на пять минут](USE_CASES.md#демо-сценарий-на-пять-минут), управление контроллерами —
[docs/SCADA.md](SCADA.md#сценарий-демонстрации).

## Что происходит при первом старте

1. Создаётся хранилище `backend/data/twin.db` и заполняется из файла кейса
   `docs/case/Кейс_Цифровой_двойник_Тестовые_данные.docx`: линии, простои, качество, план месяца. Каталог
   `backend/data/` в `.gitignore`; чтобы начать с чистого листа — удалите его или нажмите «Сбросить к файлу кейса»
   в админке.
2. Поднимается OPC UA-сервер симулятора ПЛК на `opc.tcp://127.0.0.1:4840/allur/plcsim`, и SCADA подключается к нему
   тем же клиентом, которым подключалась бы к заводу. Если порт занят, двойник не падает: симулятор переходит
   в режим без сети, причина видна в сводке SCADA.
3. Модели ИИ обучаются в фоне (несколько секунд). Двойник доступен сразу, прогнозы появляются по готовности.

## Порты

| Порт | Кто занимает | Если занят |
|---|---|---|
| 5173 | Vite, фронтенд | `npm run dev -- --port 5174` |
| 8000 | FastAPI: REST, WebSocket, SSE | поднять на другом порту и указать фронтенду: `ALLUR_API_TARGET=http://127.0.0.1:8001 npm run dev` |
| 4840 | OPC UA-сервер симулятора ПЛК | `PLCSIM_ENDPOINT=opc.tcp://127.0.0.1:4841/allur/plcsim` или `SCADA_MODE=sim` — симулятор без сети |

## Ключ OpenAI для ИИ-ассистента — необязательно

Без ключа работает всё, кроме ответов ассистента своими словами: он переходит в офлайн-режим и собирает сводку
по правилам из тех же данных. С ключом:

```bash
cp backend/.env.example backend/.env   # и впишите свой ключ
```

`backend/.env` в `.gitignore`, переменная окружения важнее файла.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TWIN_DB` | `backend/data/twin.db` | хранилище показателей; `:memory:` — не сохранять между запусками |
| `SCADA_MODE` | `opcua-sim` | `opcua-sim`, `sim`, `plant`, `off` — [docs/SCADA.md](SCADA.md) |
| `SCADA_DB`, `SCADA_CONFIG`, `SCADA_USERS`, `PLCSIM_ENDPOINT` | — | историк тревог, реестр ПЛК, учётные записи, адрес симулятора |
| `OPENAI_API_KEY`, `AI_MODEL` | — / `gpt-4.1` | ассистент и сменный отчёт — [ИИ-аналитик](AI.md) |
| `AI_MODE`, `AI_LLM` | включены | `AI_MODE=off` — без моделей ИИ, `AI_LLM=off` — только офлайн-ассистент |
| `ALLUR_API_TARGET` | `http://127.0.0.1:8000` | куда Vite проксирует `/api` |

## Сборка для показа

```bash
cd frontend
npm run build     # tsc --noEmit + Vite: три страницы в frontend/dist
npm run preview   # раздаёт сборку, /api проксируется так же
```

Статику из `frontend/dist` раздаёт любой сервер, но `/api` должен проксироваться на FastAPI — иначе двойник
останется без данных.

## Windows

Из корня проекта, без активации окружения:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

## Если что-то не работает

- **Пустые графики, «нет данных»** — бэкенд не поднят или фронтенд проксирует не туда: проверьте
  http://localhost:8000/api/health и `ALLUR_API_TARGET`.
- **3D-сцена не рисуется** — в браузере нет WebGL 2 или он отключён (`chrome://gpu`). Сцена сообщает об ошибке
  и не ломает остальные разделы.
- **Мало кадров** — кнопка настроек в сцене включает экономичный режим; `?perf` в адресе выводит в консоль FPS
  и число draw calls. При просадке сцена сама снижает плотность пикселей.
- **«OPC UA-порт недоступен» в сводке SCADA** — порт 4840 занят другим процессом, см. таблицу портов.
- **`pip install` падает на numpy или scikit-learn** — обновите pip (`pip install -U pip`); на версиях Python
  ниже 3.11 готовых колёс для numpy 2 может не быть.
- **E2E не стартуют** — Playwright берёт Python из `.venv` в корне и ждёт Chromium: `npx playwright install chromium`.

## Проверки

| Что | Команда | Объём |
|---|---|---|
| Расчёты, импорт, хранилище, симуляция, прогноз, SCADA, ИИ | `cd backend && python -m unittest discover -s tests -v` | 99 тестов, ~2 мин |
| Типы и сборка фронтенда | `cd frontend && npm run build` | tsc + Vite, три страницы |
| GLB-модели и геометрия | `cd frontend && npm run models:test` | 32 теста (Node.js 22.18+) |
| Пользовательские сценарии | `cd frontend && npm run test:e2e` | 19 тестов Playwright |

E2E запускает отдельные FastAPI (8010, `SCADA_MODE=sim`) и production preview (5180), перед тестами собирает
фронтенд; при первом запуске установите Chromium: `npx playwright install chromium`. Проверяются отказ, очередь,
восстановление, координаты кузовов в 3D, кровля, пауза, конец смены, сценарии ремонта, HTTP-резерв, ошибки API,
офлайн-ресурсы, переключение разделов без пересоздания сцены, геометрия панелей на разных экранах и пульт HMI.
Отчёт: `frontend/playwright-report`, снимки и traces: `frontend/test-results`.

Тесты бэкенда на Windows из корня проекта:

```powershell
$env:PYTHONPATH = "$PWD/backend"
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
```
